# Balanced performance pass

Baseline: `2fcbaed3` (PR #197, live 2026-11-27). After PR #197 the live median search time was 2.08 s for "leadership" and 2.32 s for "accessibility". The first search after a restart took 11.4 s.

## Changes

- **Course-media checks use one listing.** In the media bucket, each fresh check opened every manifest and then sent a size request for each of its three required files. One listing of the asset folder, made fresh on every check, now supplies those sizes. Manifests are still opened and validated each time. A deleted, empty or oversized asset is still excluded at once. If the listing is unavailable or longer than 20 pages, the check falls back to file-by-file requests. The volume store is unchanged. For 49 items, required-file requests fall from 147 to 1.
- **Smaller hero video for smaller screens.** The approved five-second animation was one 7.5 MB 4K file for every screen. It now also comes in 720p (1.5 MB), 1080p (3.0 MB) and 1440p (4.6 MB) re-encodings of the same original (SSIM 0.988–0.990 against the original scaled to the same size). The page picks the smallest file that covers the hero at the screen's pixel density, once, when the page opens. It still plays once without a button and stays off for reduced motion. The 4K original still serves the largest screens.
- **Search warmed after startup.** Five seconds after a production start, one read-only search per program scope loads the search modules and published library in the background. It stores nothing and records no query. Set `PAC_SEARCH_WARMUP=off` to disable it.
- **Build cache for accessibility originals.** `railpack.json` mounts `.cache/accessible-static-assets` as a Railpack build cache. About 1.57 GiB of build-only originals no longer goes into the runtime image. Railpack keeps caches out of the final image. The provider's default caches (`npm-install`, `node-modules`, `next`) are kept (checked with `railpack plan`). Nothing at runtime reads this folder. A cold cache behaves like today's fresh builds.

No content, sources, permissions, voices or approved visuals changed.

## Verification

TypeScript passes. The new focused tests pass: the bucket listing (pagination, nested keys, refusal), course-media checks (single listing, deleted and empty assets), and hero source selection. The existing search, supplement, storage and Home streaming tests also pass.
