# Public resource media search rollout

This optional, default-off feature indexes audio scripts attached to resources only when their current database publication is approved for unauthenticated access and model context. It does not make static-only resource parents eligible when they have no matching current database publication. Confirm that remaining coverage limitation before enabling it.

The implementation is preserved as incomplete future work. Before it can cover all public attachments, establish a trustworthy publication and model-context authorization for static-only parents and test withdrawal and edits across that boundary; never infer permission merely from an attachment's existence. Decide operational limits and error monitoring for the bounded reader, and review the source code, database grants, and behavior with production-like fixtures. The final validation is a live release check after the staged migration and opt-in enablement described below. A point-in-time aggregate check found no attached media on the currently public resource parents; it does not guarantee that future attachments will be covered.

1. Run `node scripts/testing/test-public-resource-media-postgres.mjs` against the disposable loopback fixture cluster and `node scripts/testing/run-tests.mjs --config scripts/testing/vitest.public-resource-media-unit.config.mts` for the focused application tests. Review the SQL function, access grants, and current database backup. The database test creates only synthetic local data and never connects to production.
2. Deploy the application with `PAC_PUBLIC_RESOURCE_MEDIA_INDEX=off`. Confirm existing behavior and access boundaries. Preserve the previous deploy and database backup.
3. Using the approved privileged migration connection, apply `0070_pac_dsd_public_media_scripts.sql` to the existing `pac_dsd` database. Do not rerun `bootstrap.sql` against an existing database. Confirm the function exists, is executable by `pac_dsd_app_runtime`, and is not executable by `PUBLIC`; the runtime role must not have direct table access.
4. Set `PAC_PUBLIC_RESOURCE_MEDIA_INDEX=on` and restart the service. Test with a deliberately approved, non-sensitive public audio script, then withdraw it and verify that it cannot be retrieved. Validate changed or withdrawn evidence causes an in-flight answer to be discarded. Do not use personal information in test fixtures.
5. Monitor database errors and bounded-reader limit errors. When enabled, inability to read or revalidate public media causes the Ask request to fail safely rather than return an answer derived from stale or unchecked text.

To roll back, set `PAC_PUBLIC_RESOURCE_MEDIA_INDEX=off`, restart, and verify Ask is working without this feature. After all callers have stopped, a privileged operator may revoke access and drop only `pac_dsd.read_published_media_script_lines(text,text[],text,uuid,bigint,integer)`. Do not delete media, publication records, existing functions, or roles. Retain the backup and deployment history. Re-enabling requires reapplying the function and repeating access checks.
